# 算法 01 · 哈希与前缀和

> 目标：把“重复扫描历史”改成一次查询；理解查询与插入顺序为何影响正确性。
> 实现：[two_sum / subarray_sum](../../algorithms/algorithms.h)；测试：`algorithm_tests 1`。

## 1. 两数之和：保存此前的位置

给定整数数组 a 与整数 target，返回任意一对不同下标 i<j，使 a[i]+a[j]=target；无解返回 nullopt。允许负数与重复值。例如 `[3,3]`、target=6 返回 `(0,1)`，但 `[3]` 不能拿同一个元素两次。

基线枚举所有 i<j，O(n²) 时间、O(1) 额外空间。优化的关键是固定当前 a[j] 后，只问“此前是否出现过 target-a[j]”。用哈希表记录值到较早下标的映射，查询成功即可返回。

循环开始时的不变量：seen 只记录下标小于 j 的元素。因此成功命中必然是另一位置；扫过所有 j 没命中，就不存在合法下标对。

```cpp
for (std::size_t j = 0; j < a.size(); ++j) {
    long long need = static_cast<long long>(target) - a[j];
    if (auto it = seen.find(need); it != seen.end())
        return std::pair{it->second, j};
    seen.emplace(a[j], j);
}
```

这段循环位于返回 optional 的函数中。**先查询，再插入**，否则 `[3]` 会错误匹配自己。`emplace` 保留重复值的最早位置；本题只要求任意解，无需存所有下标。补数计算先提升到 long long，避免两个 int 相减溢出。

平均时间 O(n)、额外空间 O(n)；哈希表最坏性能不是保证 O(1) 查询。若要求最坏复杂度，可以讨论排序加双指针 O(n log n)，但要保留原下标，且排序会改变顺序。

## 2. 连续子数组之和：保存此前前缀的频次

给定数组 a 和 target，统计和等于 target 的**非空连续子数组**数量。`[1,1,1]`、target=2 的答案为 2；`[0,0,0]`、target=0 的答案为 6。

定义 P[0]=0，P[r] 是前 r 个数之和。区间 `[l,r)` 的和为 `P[r]-P[l]`。因此处理右端点 r 时，问题转化为“此前有多少 P[l] 等于 P[r]-target”。

哈希表存频次而不是一个位置，因为相同前缀可以出现多次，每个位置都对应一个不同子数组。初始化 `{0:1}` 表示空前缀，允许统计从下标 0 开始的区间。

手算 `[1,-1,1]`、target=1：

| 新元素 | 当前 prefix | 需要的旧前缀 | 此前次数 | 新增答案 |
|---|---|---|---|---|
| 1 | 1 | 0 | 1 | 1 |
| -1 | 0 | -1 | 0 | 0 |
| 1 | 1 | 0 | 2 | 2 |

最终为 3。每次先把历史频次加入答案，再登记当前 prefix。若反过来，target=0 时会把长度为 0 的区间也统计进去。

平均时间 O(n)，空间 O(n)。相比先构建完整前缀数组再枚举 O(n²) 区间，这里通过历史频次一次完成统计。由于允许负数，不能套用“和太大就移动左端”的单调滑窗规则：加入负数可能使和变小。

## 3. 测试与常见失误

测试覆盖空数组、单元素、重复数、全零、负数和 int 极值的补数。随机短数组用双循环枚举所有区间计数，与前缀算法交叉比较。

返回下标不应与某个固定答案逐字比较，因为可能有多个合法解；测试应检查下标范围、不同位置、对应和，以及无解判断。前缀计数则有唯一正确数字，直接对照即可。

## 练习与面试追问

1. 手算 `[0,0]`、target=0 的 frequency 变化。**参考**：频次从 1 变 2 再变 3，新增 1、2，共 3；当前前缀不能参与本次查询。
2. 将两数之和改成返回所有合法下标对。**提示**：值映射到多个历史下标；输出本身最坏有 O(n²) 对，不能承诺总时间 O(n)。
3. 如果题目求“最长的和为 target 的区间”，该存频次还是位置？**参考**：保留每个前缀最早出现的位置，以得到最长长度；频次对应的是计数问题。
4. 为什么 prefix 使用 long long，而元素是 int？**参考**：累加范围和答案数量都可能远大于单个元素；仍需说明 long long 的输入范围前提。
