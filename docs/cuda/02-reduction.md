# CUDA 02 · 求和归约与块内协作

> 目标：将很多输入合成一个结果；证明每轮部分和的含义，处理跨 block 依赖。
> 源码：[reduce_kernel / gpu_sum](../../cuda/operators.cu)；CPU 对照：[sum](../../cuda/reference.h)。

## 1. 为什么不能让所有线程直接加到同一个 float

求 `sum(a[0..n))`。一个线程顺序累加正确但缺乏并行度；许多线程普通地执行 `out[0]+=a[i]` 会产生冲突写。全局 atomicAdd 可以组织另一种实现，但可能集中竞争一个位置，且浮点累加顺序取决于执行情况。本课采用分层归约。

先把输入分给各 block，每块得到一个部分和，再把部分和作为下一次 kernel 的输入，直到只剩一个数。跨块通信通过 global memory 和顺序启动完成，绝不把 `__syncthreads()` 当作全 grid 同步。

## 2. 一块内的树形归约

本实现固定 B=256，且 B 必须是 2 的幂。每个线程读一个输入到 `scratch[t]`；越界的尾部线程写 0，所有线程一起参与后续屏障。

以 B=8 为例，8 个输入都为 1：

| 轮次 | 执行加法的线程 | 前半部分保存的值 |
|---|---|---|
| 初始化 | 0..7 各写一个值 | 1,1,1,1,1,1,1,1 |
| stride=4 | 0..3 | 2,2,2,2 |
| stride=2 | 0..1 | 4,4 |
| stride=1 | 0 | 8 |

每轮线程 t 把 scratch[t+stride] 合到自己的槽。轮与轮之间需要屏障，下一轮才可以读取上一轮完成的部分和。不变量是每个有效槽包含一组互不重叠输入的和；下一轮合并两组，最后 scratch[0] 覆盖整个块。[块内同步规则](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html)

```cpp
scratch[t] = i < n ? input[i] : 0.0f;
__syncthreads();
for (unsigned stride = B/2; stride > 0; stride /= 2) {
    if (t < stride) scratch[t] += scratch[t + stride];
    __syncthreads();
}
```

屏障在 if 外面。尾部线程也先写入中性值，避免读取未初始化的 shared memory。线程 0 写出本块结果，其他线程不写同一输出。

## 3. 多轮归约的缓冲区生命周期

n=1000 时第一轮生成 4 个部分和，第二轮把 4 个数合成 1 个。gpu_sum 维护输入 buffer 和两个独立 scratch buffer；每轮交换 source/destination，避免一个 block 覆盖另一个尚未读取的输入。

当前教学版本每个 scratch 按原 n 分配以简化管理，用量 O(n)，不是最节省空间的实现。优化时可按第一轮部分和数量分配，但必须重新核对后续轮次容量。

n=0 在 host 直接返回 0；n=1 仍执行一次 kernel，将结果写入 scratch，避免读未初始化结果。每轮输出长度为 ceil(count/B)，B>1 时对 count>1 严格缩小，因此循环能结束。

每块做约 B-1 次加法，全部轮次总工作量 O(n)，单块合并深度 O(log B)。这不等于实际总时间必然是 O(log n)：启动、访存、硬件资源与多个 block 的调度都需要计入测量。

## 4. 浮点和不是严格结合的

实数加法满足结合律，有限精度浮点不满足。并行树改变了加法顺序，结果可能不同于 CPU 顺序累加。本课 CPU 参考使用 double，GPU 使用 float，测试用绝对误差加相对误差，而不是要求逐位一致。

大量正负项抵消后，参考和可能接近 0，这时只有相对误差没有意义。测试同时包含随机正负数、全 1、空输入，以及 255/256/257/65537 等边界。全 1 的当前测试规模在 float 精确表示整数的范围内，可精确核对。

## 练习与参考思路

1. 若 block 大小改成 192 而不改归约循环，为什么不可靠？**参考**：每轮对半的树依赖 2 的幂结构，某些元素可能未被合并。
2. 为什么尾部线程不能直接跳过初始化与协作？**参考**：槽位需要写 0，且协作屏障必须遵守统一控制流程。
3. 扩展为最大值归约，尾部该填什么？**参考**：负无穷；填 0 会破坏全负数输入。
4. 让每个线程先累加多个元素再进入 shared memory。**验收**：不重不漏的索引证明、CPU 对照、Compute Sanitizer、单独测量优化前后。
