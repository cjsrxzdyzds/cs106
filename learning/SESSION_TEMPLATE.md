# 学习日志条目模板

每次完成一个小节、出现明确误区或改变学习路线时，把下列模板填好并追加到 [LOG.md](LOG.md)，同时增量更新 [STUDY.md](../STUDY.md)。不必为纯闲聊、资料生成或每一条答复创建记录。

```markdown
## YYYY-MM-DD · 唯一短ID · 单元与小节

- **主题**：稳定单元 ID，例如 ALG-01；具体到“两数之和：先查再插”。
- **开始状态 → 结束状态**：学习中 → 待验证 / 已掌握 / 需复习等。
- **实际完成**：阅读、手算、独立实现、调试、口头复述分别说明。
- **证据**：学习者解释的关键点；代码相对路径；实际运行的测试与结果。
- **提示程度**：独立完成 / 少量提示 / 给出关键思路 / 展示答案后复述。
- **问题与更正**：具体反例、误解、修复；无证据则写“尚未观察到”。
- **尚未验证**：还有哪个边界、解释、GPU 环境或迁移题没有检查。
- **下次第一步**：一个可直接执行的小任务，不写模糊的“继续学习”。
- **复习触发**：下次同主题开始时检查什么；只有需要时设置日期。
```

记录要求：

- 自述标明“学习者自述”；助手运行参考实现标明“工程验证”。
- 未回答的问题是挂起题，不是错题；答案已给出后的复述不算独立解题。
- 代码链接到仓库实际存在的文件；没有文件时记录手算或解释即可，不编造证据。
- 一条记录尽量控制在十行左右，不复制完整对话，也不添加与学习无关的个人信息。
- 多个 chat 同时工作时，写前重读当前文件，只合并自己观察到的增量；不要用旧快照覆盖其他会话记录。
