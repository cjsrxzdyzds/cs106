# 算法 05 · BFS 最短路与拓扑排序

> 目标：从树推广到有环图；说明为什么某种访问顺序能产生正确答案。
> 实现：[bfs_distances / topological_order](../../algorithms/algorithms.h)；测试：`algorithm_tests 5`。

## 1. 图的输入契约

图使用邻接表 `vector<vector<size_t>>`，编号为 0..V-1，graph[u] 存从 u 出发的有向边终点。允许重复边和自环；邻接表出现越界编号时抛异常。无向图需要调用者添加两个方向。

图与树的重要区别是节点可能被多条路径到达，也可能有环。树上无需 visited 的遍历直接搬到图上，可能重复工作甚至无限循环。

## 2. 无权最短路径

给定源点 source，返回它到所有节点的最少边数，不可达为 nullopt。空图没有合法 source。例：边 `0→1, 0→2, 1→3, 2→3`，从 0 出发的距离为 `[0,1,1,2]`。

BFS 的队列按距离非递减处理节点。源点距离 0，弹出 u 时，对尚未发现的邻居 v 赋 `distance[v]=distance[u]+1`，立刻标记并入队。

为何第一次发现就是最短？若存在更短的到 v 的路径，其前驱距离更小，应该在当前层之前就被处理，v 也会更早被发现，矛盾。这里每条边代价都相同；有不同权重时，FIFO 顺序不再保证最小代价。

入队时标记而不是出队时标记，可以让重复边或多父节点只造成一次入队。时间 O(V+E)，空间 O(V)，不含图存储；实现的输入校验也扫描一次边，复杂度不变。

想返回实际路径时，第一次发现 v 就保存 parent[v]=u，结束后从目标逆着 parent 回溯。不可达不能对一个默认 parent 数组盲目追踪。

## 3. 依赖关系的拓扑排序

边 u→v 表示必须先完成 u，才能完成 v。输出一个满足所有依赖的节点排列；有环返回 nullopt。空图的空排列合法，因此不能用“空 vector”同时表达有环和空图。

Kahn 算法计算每个节点入度，把所有入度为 0 的节点加入队列。弹出 u 相当于完成 u，删除其出边：每个邻居入度减一，减到 0 就进入就绪队列。

```text
0→2，1→2，2→3
初始就绪：0、1
完成 0：2 仍有一个前置依赖
完成 1：2 入度变 0，可以加入
完成 2：3 可以加入
```

不变量：当前入度等于来自“尚未输出节点”的边数。因此队列中每个节点都可以安全输出。输出不足 V 个，说明剩余图没有入度为 0 的节点；有限图中沿前驱不断追踪最终形成环。

时间 O(V+E)、空间 O(V)。重复边在构造入度和移除边时均计算一次即可一致处理。拓扑序不一定唯一；测试应核对每条边的先后和节点恰好出现一次，不要只和一个固定序列比较。

## 4. 与线程池的连接

任务依赖图可以用类似拓扑思想找可执行任务，但实际调度器不能仅把本章代码套上线程：完成状态和入度更新需要同步，任务异常可能使后继不能运行，还要设计取消与结束检测。

尤其不要让线程池中每个任务阻塞等待尚未调度的后继。应先明确依赖方向，再把“已满足前置条件”的任务提交给可用 worker。

## 练习与参考思路

1. 带权图上 BFS 为什么失效？举 `0→1` 权重 10，`0→2→1` 各权重 1。**参考**：边数少不代表代价低；非负权可进一步学习 Dijkstra。
2. 如何求多源最短距离？**提示**：把所有源点距离初始化为 0，同时入队，相当于从同一层开始。
3. 如果需要字典序最小的拓扑序？**参考**：用最小堆管理就绪节点，复杂度增加到约 O(E+V log V)。
4. 如何测试随机图最短距离？**参考**：小规模上用 Floyd-Warshall 独立对照；本仓库测试采用这种方式，并用可达关系检查是否存在环。
