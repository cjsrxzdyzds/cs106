# 算法 06 · 动态规划与回溯

> 目标：把“搜索所有可能”拆成两种需求：只求最优值，或确实需要所有答案。
> 实现：[coin_change / combinations](../../algorithms/algorithms.h)；测试：`algorithm_tests 6`。

## 1. 最少硬币：状态代表一个完整子问题

给定正整数面额列表，每种可用任意次，求凑出 amount 所需最少硬币数。amount>=0，凑不出返回 -1；空面额列表只可以组成金额 0。重复面额允许，0 和负面额非法。

例如 `[1,2,5]` 凑 11，需要 3 枚：5+5+1。不能对任意面额都贪心取最大值：`[1,3,4]` 凑 6，贪心是 4+1+1，而最优是 3+3。

定义 `dp[s]` 为组成金额 s 的最少枚数。最后一枚硬币若是 c，剩下必为 s-c；若剩下部分不是该金额的最优解，就可以替换为更好的解，使整体更好，因此最优子结构成立。

```text
dp[0] = 0
dp[s] = min(dp[s-c]+1)，只考虑 c<=s 且 dp[s-c] 可达
没有候选则 dp[s] = -1
```

面额为正保证所有依赖 s-c<s，所以按金额递增计算时依赖已经准备好。实现以 -1 表示不可达，先检查可达再加 1，避免用 INT_MAX 作哨兵后直接 +1 导致溢出。

时间 O(amount × 面额数)，空间 O(amount)。这是相对于金额值的复杂度，不是金额二进制输入长度的多项式界；金额极大时内存与时间都可能不实用。

本题求最少数量。若改成“有多少种组合”，初值、状态含义和循环顺序都需重新推导；不同顺序可能计算排列而非组合，不应只改一个 min 为加法。

## 2. 从 1..n 中选择 k 个数

返回所有严格递增的 k 元组合，按字典序排列；0<=k<=n，n>=0。`n=4,k=2` 的结果为 `[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]`。k=0 时有且只有一个空组合，即 `[[]]`，不是没有答案。

用 path 存当前前缀，start 表示下一个允许选择的最小值。每次选择 value 后递归从 value+1 继续，回来时 pop_back 撤销选择。递增约束直接避免 `[2,1]` 这样的重复排列。

不变量：path 严格递增且长度不超过 k；所有补充元素必须大于末尾。因此每个组合对应唯一搜索路径，不重不漏。

如果还需要 need 个元素，下一个起点不能超过 `n-need+1`，否则即使选完所有剩余数字也不够。这是安全剪枝：删掉的分支没有合法答案。

```cpp
path.push_back(value);
search(value + 1);
path.pop_back();
```

忘记最后一步会污染兄弟分支；直接保存对 path 的引用会让所有结果共享一个不断变化的对象。参考实现在找到答案时复制 path。

输出有 C(n,k) 个组合，每个长度 k。对 k>=1，时间可按 O(k·C(n,k)) 理解，输出空间同阶，递归和 path 额外空间 O(k)；k=0 单独为 O(1)。这是输出敏感算法，n 较大时“枚举全部”本身就不可行，不能承诺靠剪枝变成线性时间。

## 3. 何时动态规划，何时回溯

最少硬币会反复询问相同剩余金额的最优解，可以按状态共享结果；组合枚举中，不同前缀即使还需选择相同数量，也必须输出不同完整答案，不能简单用一个“访问过此状态”就剪掉。

若组合题只问数量，则可以学习组合数递推或 DP，不必真的生成所有组合。先问清“返回一个解、最优值、数量还是全部解”，再选择算法。

## 4. 验证与结课

硬币测试用金额状态图 BFS 作独立参考：从 0 出发，每加一枚硬币走一条边，到 amount 的最少边数就是答案。组合测试在 n<=9 时遍历所有位掩码，按选中数目过滤，与回溯结果逐一比较。

1. 为硬币题恢复一组最优面额。**提示**：dp 更新时记录选择，沿金额递减重建；不可达需先判断。
2. 为 `[1,3,4]`、amount=6 手写每个 dp 值。**参考**：`0,1,2,1,1,2,2`。
3. 如果输入有重复候选值，如何枚举不重复组合？**提示**：先明确元素按位置还是值区分；按值去重通常需排序并跳过同层重复，不能直接套 1..n 的唯一值模型。
