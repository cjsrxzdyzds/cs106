# 算法 03 · 单调栈与单调队列

> 目标：解释为何可以永久删除一个候选；理解摊还 O(n)，而非机械数循环层数。
> 实现：[next_greater_distance / sliding_max](../../algorithms/algorithms.h)；测试：`algorithm_tests 3`。

## 1. 右侧第一个严格更大元素

对每个 a[i]，返回到右边第一个严格大于它的元素的距离；不存在时返回 0。输入 `[2,1,2,4,3]`，结果 `[3,1,1,0,0]`。

基线从每个 i 向右扫描，O(n²)。改为按从左到右扫描，把尚未找到答案的下标存在栈中。栈从底到顶的值非递增。遇到 a[i] 时，只要它严格大于栈顶，栈顶的答案就是 i-j，随后弹出。

```text
输入到 2：栈 [(0,2)]
输入到 1：栈 [(0,2),(1,1)]
输入到 2：弹出 (1,1)，距离 1；栈 [(0,2),(2,2)]
输入到 4：依次解决位置 2 和位置 0
```

为何一定是第一个？若 j 和 i 之间已出现更大值，j 在那一轮就应被弹出，不可能仍留在栈内。相等不能弹出，因为题意要求严格更大。

栈存下标，不只存值，才能计算距离、区分重复值。循环内虽然有 while，但每个下标最多入栈一次、出栈一次，总 O(n) 时间、O(n) 空间，这就是摊还分析。

## 2. 长度 k 的窗口最大值

给定数组与 1<=k<=n，输出每个连续长度 k 区间的最大值。`[1,3,-1,-3,5,3,6,7]`、k=3，返回 `[3,3,5,5,6,7]`。空输入没有合法 k，本接口抛 invalid_argument。

每个窗口扫描 O(k)，总 O(nk)。单调队列维护仍可能成为未来最大值的下标：队首是当前最大值，队列下标递增，对应值严格递减。

处理 i 时按顺序：

1. 删除已经离开窗口的队首下标。
2. 若队尾值小于或等于 a[i]，删掉队尾。
3. 将 i 加入队尾，窗口长度达到 k 后输出队首值。

删除队尾的理由是**支配关系**：新元素不小于旧元素，而且出现更晚、过期也更晚。未来任何同时包含二者的窗口都不需要旧元素；旧元素离开后也不会再次回来。

这里相等时可以删除旧元素，和上一题“严格更大”的处理不同：一个在寻找比较关系，一个在保留最大值候选，不能背一个比较符号通用。

每个下标最多从一端删除一次，总 O(n) 时间、O(k) 辅助空间，不含输出。下标无符号时，先检查 i>=k 再计算 i-k，避免下溢。

## 3. 栈、堆、队列如何选择

寻找右边第一个更大值，需要后来的元素解决一串等待者，栈合适。固定窗口最大值要从队首移除过期元素，从队尾淘汰劣势候选，双端队列合适。堆也能处理最大值，但常需额外管理过期项；仅用延迟删除时堆大小可能累积到 O(n)，不要随口宣称空间永远 O(k)。

## 练习与参考思路

1. 手算全相等数组 `[2,2,2]`。**参考**：严格更大距离全 0；窗口最大值全 2；两种结构的相等规则不同。
2. 改成窗口最小值。**参考**：反转队尾比较关系，同时保留下标过期逻辑。
3. 增加单调递增、递减、k=1、k=n 的测试。**验收**：与每窗 max_element 对照，而非只核对输出长度。
4. 为什么有两层循环仍是 O(n)？**参考**：按元素的生命周期计费，每个元素最多被加入和移除各一次。
